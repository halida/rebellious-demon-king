# 站点适配笔记

> 记录已验证的站点结构，以及"遇到新站怎么改"的通用套路。
> 用 [`下载小说.py`](下载小说.py) 跑：`--probe` 先探测，再决定要不要加适配。

---

## 1. 已验证站点

### ① 小说01（xiaoshuo01.com）★ 首选
- 目录：`https://www.xiaoshuo01.com/{分类}/{书号}/`，分页 `index_2.html …`
- 章节：`https://www.xiaoshuo01.com/{分类}/{书号}/{章节id}.html`
- 正文容器：`<article class="font_max">`（整站统一）
- 分页：同一章 `…_{章节id}_2.html`、`_3.html`；页内有 `第(n/m)页` 标记
- 下一章链接：`<a id="next1" href="…">`，翻页判定：`href` 需匹配 `^/{分类}/{书号}/{章节id}_\d+\.html$`
- 实测：《反叛的大魔王》1523 章 0 失败；《大奉打更人》997 章目录识别正常
- 坑：目录页会混入"最新章节"重复链接 → 按 id 去重即可

### ② 听雨中文网（tingyuzw.com）⚠ 残缺 + AJAX
- 目录：`https://www.tingyuzw.com/info/{书号}/`，章节 `…/info/{书号}/{id}.html`
- **正文不在 HTML 里**：前端 `chapter.js` 走
  ```
  POST /home/index/ajaxchapter
  id={书号} & eKey={hash} & cid={章节id} & basecid={章节id}
  翻页再加：nextpage、pagehash
  ```
- 退路：可直接访问 `…/{id}_N.html` 的转码分页
- **两个致命问题**：
  1. 目录**残缺**（本书缺官方第 1363—1423 章及后记）
  2. 章节 id 与起点发布顺序**有错位**（1167—1169 重号、1366 处重新起编），且会做**同音字替换防抄**
- 抓取脚本见 `../语料/fetch_ch.py`、`fetch2.py`、`fetch3.py`、`fetch_jina.py`
- 站点限流时走代理会 SSL 握手超时，**直连反而正常**

### ③ 起点 / QQ阅读（阅文官方）★ 正版优先
- 书籍页：`https://book.qq.com/book-detail/{书号}`；目录 `https://book.qq.com/book-chapter/{书号}`
- 章节：`https://book.qq.com/book-read/{书号}/{序号}`；另一域名 `https://xiaoshuo.qq.com/read/{书号}/{序号}`
- 正文容器：`<div id="article" class="chapter-content isTxt">`
- **VIP 章网页端只返回开头一段**（会看到"上QQ阅读APP看后续精彩内容"）→ 不能当全书源
- **可用部分**：上架前的免费章（本书是第 1—135 章），免费且完整，适合"先读官方再决定要不要离线"
- 每章页带"本章想法"书友评论区（剧透重）
- 整本离线阅读的正确方式：**起点读书 / QQ阅读 APP 的「下载」功能**

### ④ 其他笔趣阁系（结构大多同模板）
- 品书、笔趣阁、xsune 等：通常是 `/{分类}/{书号}/` + `<div id="content">`
- 用 `--probe` 验证即可；若命中 `div#content` / `div.content`，**通用下载器零改动可用**
- 注意甄别：盗版站 + 下载站 + 聚合站混杂，优先选**有完整目录、无弹窗广告、URL 稳定**的

## 2. 遇到新站怎么适配（通用套路）

### 第 1 步：探测
```bash
python3 下载小说.py --probe "https://新站/分类/书号/"
```
看输出：书籍前缀对不对、正文容器命中哪个、目录多少章。

### 第 2 步：三种常见偏差与对策

| 现象 | 原因 | 对策 |
|---|---|---|
| 目录只抓到 1 页 | 目录分页不是 `index_N.html` | 打开浏览器翻页看真实 URL，把模式加进 `Site.collect_index()` |
| 章节全是空 | 正文容器不是候选里的 | 在章节页搜 `id="content"`/`class="txt"`/`content`/`txt` 等特征，加进 `CONTENT_SELECTORS` |
| 章节被截断 | 该站章内分页 URL 不是 `_N.html` | 抓一页后打印 `<a id="next1">` 的 href，看它的真实规律再改翻页正则 |

### 第 3 步：改 `下载小说.py` 的三个点
1. `CONTENT_SELECTORS`：加你的正文容器正则（顺序即优先级）
2. `Site.collect_index()`：改目录分页模式
3. `Site.fetch_chapter()`：改翻页判定（当前规则：`next1` 必须匹配 `^/{前缀}/{章节id}_\d+\.html$`）

### 第 4 步：验证三件事
```bash
# 小样本
python3 下载小说.py --book "..." --limit 3 --outdir _t
# ① 首章正文完整吗？② 有没有"第(1/3)页"残留？③ 最后一页接得上吗？
grep -c "第(1/.*)页" _t/*全书.txt
```

## 3. 调试速查

```bash
# 看原始 HTML 里正文容器长什么样
curl -s --noproxy '*' "章节URL" | grep -o '<div id="[a-z]*"\|<article[^>]*>\|class="[a-z]*content[a-z]*"' | sort -u

# 看翻页链接
curl -s --noproxy '*' "章节URL" | grep -o 'id="next[0-9]*"[^>]*href="[^"]*"'

# 看目录分页
curl -s --noproxy '*' "目录URL" | grep -o 'index_[0-9]*\.html' | sort -u | tail -5
```

## 4. 通用调试心法

- **抓不到 ≠ 没有**：先在浏览器里打开该 URL 看源码；很多站是 JS 渲染，源码里什么都没有。
- **先手工跑通一章，再上批量**：单章手工 curl 成功再写脚本，能省掉 80% 的调试时间。
- **同一站的多个镜像往往同模板**：搞定一个，其余的改 base URL 即可。
- **把"抓到的章数"和"官方章数"写在日志里**：数量对不上立刻能发现残缺，不用等全书跑完才发现。
