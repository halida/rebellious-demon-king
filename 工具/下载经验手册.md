# 网络小说离线下载 · 经验手册

> 这份手册来自 2026-10-26 实操下载《反叛的大魔王》（1523 章 / 805 万字 / 0 失败）的全过程，
> 包含**可直接复用的决策路径、站点结构识别、网络坑、抓取坑与验收标准**。
> 配套工具：[`下载小说.py`](下载小说.py)（通用下载器）、[`校验完整性.py`](校验完整性.py)（成品体检）。

---

## 0. 总原则（先看这一段）

1. **优先官方**：官方站能免费读的章节 → 官方 APP 离线缓存 → 镜像站兜底。镜像站是最后手段。
2. **先验源，再抓**：动手前先确认"这个源的章数和首尾章对不对"，**残缺镜像是最常见的坑**。
3. **能续传就别重来**：任何脚本都要"边抓边落盘 + 原子写 + 可重入"，否则一个 bug 会让你重跑半小时。
4. **低并发 + 有礼貌**：并发 2–4、每请求随机 0.3–1.2s 间隔；不要为了快把站压垮。
5. **成品必须体检**：章数、缺章、分页残留、重复、字数、首尾章名——全过才算完成。

## 1. 选源决策树

```
想要一本小说的 TXT
        │
        ├─ 官方平台有这本书？
        │    ├─ 是 → ① 官网/APP 读"免费章节"（起点、QQ阅读通常免费开放前 100+ 章）
        │    │        ② 已购 → APP「下载/离线缓存」整本缓存到本地（最合规）
        │    │        ③ 官方站网页端对 VIP 章只返回开头一小段 → 不能当全书源
        │    └─ 否 → 走镜像站
        │
        └─ 只能用第三方镜像？
             ├─ 先验完整性：镜像目录章数 vs 官方目录条数；首/末章名是否与官方一致
             │    ├─ 一致 → 可抓
             │    └─ 不一致（少几十~上百章）→ 换源！别抓了才发现缺结局
             ├─ 抓取方式：静态 HTML / 分页 HTML / AJAX POST（见第 3 节）
             └─ 礼貌限速 + 断点续传
```

**本次实例**：官方 QQ阅读 只免费到第 135 章；第一本镜像（听雨中文网）**目录止于 id 1533，缺官方第 1363—1423 章及后记**，正好把结局切掉；换第二本镜像（小说01）才拿到完整的 1523 章。

## 2. 怎么验证一个源"全不全"（残缺镜像识别）

| 检查 | 做法 | 症状 |
|---|---|---|
| 章数对比 | 官方 `book.qq.com/book-chapter/<书号>` 的目录条数 vs 镜像目录条数 | 镜像明显少 → 残缺 |
| 首章对比 | 官方第 1 章标题 vs 镜像第 1 章 | 镜像首章不是"第一章/序章" → 镜像从中间开始 |
| **末章对比（最关键）** | 镜像最后一章是不是"完本/终章/后记" | 镜像停在"诸神的黄昏（132）"这种半截 → **缺结局** |
| 章节 id 连贯性 | 镜像 id 是否连续无空洞 | 有空洞 → 抓取时会有空文件 |
| 官方章号 vs 镜像 id | 两者一般**不一致**（见第 4 节） | 别拿镜像 id 当官方章号引用 |

> 经验值：镜像站入库顺序 = 章节顺序，**所以镜像数字 id 升序 ≈ 书中顺序**，与官方章号无关。

## 3. 站点结构的三种类型（自动识别方法）

### A. 静态 HTML 型（最常见：笔趣阁/小说01/品书 等模板）
```
目录页：https://站点/分类/书号/           （分页：index_2.html、index_3.html …）
章节页：https://站点/分类/书号/章节id.html
正文容器：<article> / <div id="article"> / <div id="content"> / <div class="content">
```
### B. 分页型（同一章拆成多页）
```
章节页第 2 页：…/章节id_2.html     正文里带 "第(1/3)页" 标记
翻页依据：页内 <a id="next1" href="…_2.html">（注意 next 链最终会指向"下一章"，必须用正则只认同章 id）
```
### C. AJAX 型（正文不在 HTML 里）
以听雨中文网为例：正文由前端 `chapter.js` 通过
```
POST /home/index/ajaxchapter
参数：id=<书号>&eKey=<hash>&cid=<章节id>&basecid=<章节id>（翻页再加 nextpage、pagehash）
```
> 此类站点一般也能直接访问 `<id>_N.html` 的转码分页，可作为退路。

### 自动探测
```bash
python3 下载小说.py --probe "https://站点/分类/书号/"
```
输出：站点根、书籍前缀、各正文容器候选命中情况、目录总章数与首/末章名。

## 4. 章节 id ≠ 官方章号（最容易引用出错的地方）

- 镜像站的 id 是**入库序号**，与平台发布的"第 N 章"无对应关系。
- 官方章号会因"作者单章公告"而错位：本书镜像 id 137 对应官方第 135 章（前面夹着 4 篇公告）。
- 引用时写"**卷次 + 篇目锚点**"（如"卷三《七罪宗》"）最安全；非要写章号就写"官方第 N 章"并注明来源。

## 5. 网络层：本次踩到的三个坑

### 坑 1：环境代理把站点限流了 —— 会误判成"被封"
- 现象：走 `http_proxy=proxy.llj.click:8080` 时随机 SSL 握手超时；同一 URL 直连只要 1–2 秒。
- 本次还遇到"直连反而更慢"的情况（站点限速的是共享代理出口 IP）。
- **解法**：先直连，失败再走代理；本次通用下载器默认 `ProxyHandler({})` 直连，`--use-proxy` 才走代理。
  ```bash
  no_proxy='*' python3 下载小说.py --book "..."     # 直连（推荐）
  ```
- **判断口诀**：超时 ≠ 封禁。换出口 IP / 换 UA / 降并发再试。

### 坑 2：并发不是越高越好
- 6 线程在本站可以跑满，但两次并行实例叠加同一站 → 双方一起变慢（互相挤占站点连接配额）。
- 推荐 2–4 线程；章节间随机 0.3–1.2s。

### 坑 3：Cookie 会话
- 某些站点首访要种 Cookie；用 `http.cookiejar` + 一个 opener 贯穿全程，比每次新建连接稳。

## 6. 抓取层：脚本必须具备的 6 个特性（本次全部用上了）

| 特性 | 为什么 | 实现 |
|---|---|---|
| **边抓边落盘** | 内存里攒完再写 = 一个 bug 全白干（本次就踩了：写文件时解包报错，1523 章跑完 30 分钟全丢） | 抓到一章立刻写单章文件 |
| **原子写** | 中断不留半截文件 | 写 `xxx.tmp` → `os.replace()` |
| **断点续传** | 已存在且大小 > 阈值的章节直接跳过 | `if os.path.exists(path) and size>150: skip` |
| **失败重试** | 单章失败不阻塞整体 | 每章独立 try；失败记 `missing.txt`；多轮重试 |
| **请求级退避** | 抖动比固定 sleep 活着久 | 指数退避 + 随机抖动 |
| **完整目录快照** | 重试循环会改写待抓列表，写合并文件时要用**完整目录** | `all_order = list(order)` 单独留一份 |

> 附带经验：管道 `| tail -40` 会**缓存实时输出**，看不到进度；要么直接输出，要么写日志文件（`> 日志.txt 2>&1`）。

## 7. 正文提取与清洗清单

```python
<br> → 换行 ; </p> → 空行 ; 去掉全部标签 ; 解 HTML 实体(&nbsp; &amp; &quot; &ldquo; …)
去掉分页标记：第(1/3)页 / 第 1/3 页
```
- 分页标记必须删，否则成品 TXT 里会到处是"第(2/5)页"。
- 标题：`<title>` 里常有"xxx在线阅读-站名""xxx最新章节"，要用正则裁掉尾巴；裁不干净就退回目录页里抓到的标题。
- **有些"章节"是作者的公告/致歉/请假（几十到几百字）**——短章是正常的，不要当成抓取失败。本次 1523 章里有 41 篇短章，全部是公告。

## 8. 输出规范（本次采用）

```
原文/
├── <书名>-全书.txt          合并本：文件头含书名/作者/来源/版权声明，每章用 ==== 分隔
├── <书名>-章节索引.txt      速查表：序号 \t 章节id \t 标题 \t 字数
├── 章节/<id>.txt            单章文件
└── missing.txt              缺失章清单
```
文件头固定写清来源与"仅供个人学习、请支持正版"，这是自我约束也是礼貌。

## 9. 成品体检（用 `校验完整性.py`）

```
python3 校验完整性.py --dir 原文 --title "书名"
```
必看 6 项：
1. **章数** 与索引一致、单章文件无缺无多
2. **可疑短章**（<800 字）——逐个确认是"公告"还是"抓断"
3. **分页标记残留 = 0**
4. **重复标题**——允许（多篇"致歉"），但要看是不是抓重
5. **首/末章名** —— 末章必须是终章/后记，不是半截
6. **总字数** 与预期量级相符（730 万字的书，量级对不上就是缺了）

本次结果：1523 章 / 0 缺 / 0 分页残留 / 末章《发新书了~！》✔

## 10. 换一本书的完整流程（本次实测）

```bash
# 0) 建目录
mkdir -p 我的新书/原文 && cd 我的新书

# 1) 先探测结构（不抓正文，30 秒内出结果）
python3 工具/下载小说.py --probe "https://站点/分类/书号/"

# 2) 小样本试抓 5 章，确认正文容器与分页都正确
no_proxy='*' python3 工具/下载小说.py --book "https://站点/分类/书号/" \
        --limit 5 --workers 2 --outdir 原文 --title "书名" --author "作者"

# 3) 人工抽查：读第一章和最后一章，确认不是残缺镜像
head -50 原文/书名-全书.txt

# 4) 全量抓（可随时中断，再跑同一条命令即续传）
no_proxy='*' python3 工具/下载小说.py --book "..." --workers 3 --outdir 原文 --title "书名"

# 5) 体检
python3 工具/校验完整性.py --dir 原文
```

## 11. 版权与边界（每次都要记住）

- 作品版权归原作者与连载平台；下载来的文本**仅供个人离线阅读**，不要二次分发、转售或商用。
- **优先用官方**：起点/QQ阅读 APP 的离线缓存既能整本带下来，又直接支持作者。
- 在自己的笔记/书评里引用原文要**克制**（短引、注明出处），不要整段搬运。
- 抓取脚本请**只用于自己真正要读的那本书**，保持低并发，别把人家站点当矿机。
- 遇到付费墙：买它，而不是绕过它。
